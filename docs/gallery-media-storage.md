## Сделано: хранилище фото и reverse proxy

Фото полосы «Что вас ждёт» на главной больше не лежат в репозитории — владелец заливает их
в MinIO через веб-консоль, без коммита и пересборки сайта. Наружу смотрит nginx, фото отдаются
с того же домена по `/media/hero/...`.

**Рабочее описание — в [CLAUDE.md](../CLAUDE.md)**, раздел «Фото главной: хранилище и reverse proxy»:
раскладка бакета, правила именования, порядок заливки, поведение при отказе хранилища, все
грабли конфигурации nginx и порядок включения TLS. Здесь это не дублируется, чтобы не разъезжалось.

Проверено вживую: фото отдаются с домена сайта с нужными заголовками и 304 по ETag; наружу проходит
только `GET`/`HEAD` на `.webp` (перечисление бакета, не-webp и PUT — 404/403); S3 API снаружи
недоступен; `limit_req` отбивает 336 из 400 запросов при 3000 rps; лимитер сайта считает по
реальному IP клиента (исчерпанный лимит с одного адреса не мешает другому); перезаливка фото
меняет версию в URL; при остановленном MinIO главная продолжает отвечать 200.

## Задел: видео

Вопрос владельца от 24.08.2026: как выкладывать несколько роликов по 3–5 минут.
Ответ: **обычный MP4, потоковая передача (HLS/DASH) не нужна.**

### Почему хватает MP4

`<video>` шлёт `Range`-запросы, MinIO их поддерживает, nginx пробрасывает — браузер играет
с первых секунд и умеет перематывать, весь файл заранее не качается. Это и есть progressive
streaming, просто без отдельного протокола.

HLS окупается при роликах длиннее ~10 минут, адаптивном битрейте под слабую мобильную сеть,
прямом эфире или DRM. Цена — нарезка на сегменты, 2–3 рендишена вместо одного файла, плейлисты
и **JS-плеер**: Safari играет HLS нативно, Chrome и Firefox — нет, то есть придётся вендорить
hls.js в [js/vendor/](../src/frontend/ui.public.web/wwwroot/js/vendor/). Для нескольких коротких
роликов несоразмерно.

### Три вещи, которые надо сделать правильно

**1. `faststart` — критично.** Если `moov`-атом лежит в конце файла (по умолчанию у многих
кодировщиков), браузер обязан скачать ролик целиком, прежде чем показать первый кадр:
```bash
ffmpeg -i in.mov -c:v libx264 -crf 23 -preset slow -pix_fmt yuv420p \
       -c:a aac -b:a 128k -movflags +faststart out.mp4
```
Проверка: `ffprobe -v trace out.mp4 2>&1 | grep -m2 -E 'moov|mdat'` — `moov` первым.

**2. `preload="none"` + постер.** Иначе страница с тремя роликами начнёт тянуть десятки мегабайт
до того, как посетитель нажмёт play:
```html
<video controls preload="none" poster="/media/video/poster/010-teriberka.webp"
       width="1280" height="720">
  <source src="/media/video/010-teriberka.mp4" type="video/mp4">
</video>
```

**3. Кодек — H.264 + AAC.** Играет везде без исключений. VP9/AV1 дают файл вдвое легче, но
кодируются в разы дольше, а поддержка AV1 в Safari зависит от железа; при желании добавляются
вторым `<source>`.

### Вес и трафик

Ориентиры для съёмки природы (море, снег, движение — картинка высокоэнтропийная):

| Разрешение | Битрейт | 3 мин | 5 мин |
|---|---|---|---|
| 720p | ~2,5 Мбит/с | ~55 МБ | ~90 МБ |
| 1080p | ~4 Мбит/с | ~90 МБ | ~150 МБ |

Делать **одну версию 1080p с CRF 23**, а не набор качеств. Уходит за ~150 МБ — резать
длительность, а не переходить на HLS.

**Трафик — отдельная статья расходов.** 100 просмотров ролика на 90 МБ = 9 ГБ исходящего.
`limit_req` на `/media` ограничивает частоту, но не объём: для видео это повод посмотреть
на тариф VPS или поставить CDN.

### Правки конфигурации

[Конфиг nginx](../infra/nginx/templates/default.conf.template) пускает наружу **только `.webp`**
и принудительно ставит `Content-Type: image/webp`. Под видео — отдельный `location` рядом:

```nginx
location ~* ^/media/(?<vid>.+\.mp4)$ {
    limit_except GET HEAD { deny all; }
    limit_req zone=media burst=30 nodelay;

    proxy_pass http://minio:9000/${MEDIA_BUCKET}/$vid?;
    proxy_http_version 1.1;
    proxy_set_header Host minio:9000;

    proxy_hide_header Content-Type;
    proxy_hide_header Server;
    add_header Content-Type "video/mp4" always;
    add_header Cache-Control "public, max-age=${MEDIA_MAX_AGE}" always;
    add_header X-Content-Type-Options "nosniff" always;
}
```

- **Не включать mp4 в `gzip_types`** — h264 уже сжат, а сжатие ломает `Content-Length`
  у диапазонных запросов.
- **Не трогать `Accept-Ranges`** от MinIO — на нём держится перемотка. `proxy_buffering`
  для видео лучше выключить (`proxy_buffering off`), иначе nginx будет копить крупные ответы.
- **CSP сайта менять не нужно**: `media-src` в политике не задан и падает на `default-src 'self'`,
  а видео с того же origin — ровно как фото.
- Префиксы в бакете: `video/*.mp4` и `video/poster/*.webp`; постеры пройдут существующим
  `location` для webp. В анонимную политику добавить `video/*`.
- `MediaCatalog` видео листить не нужно: ролики штучные, проще перечислить в разметке страницы,
  чем заводить второй листинг бакета.
